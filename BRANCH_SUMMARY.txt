================================================================================
WHAT'S FIXED
================================================================================

Root Cause:
- ChibiOS Kinetis USB driver crashed on disconnect → reconnect → disconnect sequence
- This sequence is part of normal QMK operation (OS detection, split watchdog)
- Result: Right half would disconnect semi-randomly on QMK > 0.14.0

Solution (Hydra's PRs):
1. QMK PR #25963: MCU reset implementation for kiibohd bootloader
2. ChibiOS-Contrib PR #432: Fix Kinetis USB start/stop/disconnect crash

Benefits After Applying Fixes:
✓ Can upgrade from QMK 0.14.0 to modern versions
✓ No longer need SPLIT_MAX_CONNECTION_ERRORS error masking
✓ Proper USB state management in ISR handlers
✓ Reliable split keyboard operation

================================================================================
KEY DIFFERENCES: keyboard_config.h vs keyboard_config_fixed.h
================================================================================

OLD (keyboard_config.h):
- #define SPLIT_MAX_CONNECTION_ERRORS 65535  ← Masks USB errors
- No MCU_RESET_ENABLED
- Works on QMK 0.14.0 only
- Can't upgrade QMK

NEW (keyboard_config_fixed.h):
- SPLIT_MAX_CONNECTION_ERRORS removed  ← Not needed
- #define MCU_RESET_ENABLED  ← Enables bootloader fix
- Works on QMK 0.14.0 AND modern versions
- Allows QMK upgrades
